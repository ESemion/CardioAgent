# CardioAgent — Кроссплатформенный Web-агент
CardioAgent — это программный агент, предназначенный для выполнения задач, поступающих от центрального сервера управления. Проект разработан как кроссплатформенное решение (Windows, Linux, macOS) с упором на модульность, безопасность и надежность сетевого взаимодействия.
📋 Обзор проекта
Целью проекта является создание системы, способной автономно взаимодействовать с сервером, регистрировать новые узлы в сети и выполнять специализированные команды в многопоточном режиме.
Основные возможности
 * Кроссплатформенность: Код написан на стандарте C++17 и собирается с помощью CMake, что обеспечивает работу в различных операционных системах.
 * Безопасность: Передача данных осуществляется по защищенному протоколу HTTPS с использованием OpenSSL.
 * Многопоточная архитектура: Использование модели «Producer-Consumer» для разделения процессов опроса сервера и выполнения задач.
 * Автоматическая регистрация: Агент самостоятельно генерирует UID и получает код доступа при первом запуске.
 * Потокобезопасное логирование: Регистрация событий в файл и консоль с защитой от конфликтов доступа из разных потоков.
🛠 Технологический стек
 * Язык программирования: C++17.
 * Система сборки: CMake.
 * Библиотеки:
   * cpp-httplib — для работы с HTTP/HTTPS запросами.
   * OpenSSL — для обеспечения защищенного соединения.
 * Формат конфигурации: INI-файлы.
🚀 Быстрый старт
Требования
 * Компилятор с поддержкой C++17 (GCC, Clang или MSVC).
 * Установленная библиотека OpenSSL.
 * CMake версии 3.10 или выше.
Сборка
 * Склонируйте репозиторий:
   git clone https://github.com/ESemion/CardioAgent
cd cardio-agent

 * Создайте директорию сборки и скомпилируйте проект:
   mkdir build && cd build
cmake ..
cmake --build .

Настройка
Перед первым запуском необходимо настроить файл конфигурации:
 * Перейдите в директорию config/.
 * Создайте файл agent.ini на основе agent.ini.example.
 * Укажите адрес вашего сервера:
   server_url=https://your-server.com:8080
poll_interval=10

Примечание: UID и access_code будут сгенерированы и записаны в файл автоматически при первом успешном запуске.
🏗 Архитектура проекта
Проект разделен на несколько функциональных модулей согласно ООП-модели:
 * Agent: Центральный класс, управляющий жизненным циклом приложения, сетевыми потоками и очередью задач.
 * TaskExecutor: Модуль, отвечающий за непосредственное выполнение команд (анализ, работа с файлами и т.д.).
 * Config: Отвечает за загрузку, хранение и автоматическое обновление настроек агента.
 * Logger: Синглтон-сервис для ведения журналов работы системы.
Сетевое взаимодействие (API)
Агент взаимодействует со следующими эндпоинтами сервера:
 * POST /api/wa_reg/ — Регистрация нового агента.
 * POST /api/wa_task/ — Получение списка задач (Polling).
 * POST /api/wa_result/ — Отправка результатов выполнения (поддерживает загрузку файлов через multipart/form-data).
📂 Структура репозитория
 * Include/ — Заголовочные файлы интерфейсов.
 * Src/ — Реализация основных модулей.
 * Config/ — Конфигурационные файлы и примеры.
 * Logs/ — (Создается автоматически) Журналы работы приложения.
 * Temp/ — (Создается автоматически) Временные файлы результатов задач.
